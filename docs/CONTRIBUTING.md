# Contributing to LearnPilot

Thanks for your interest in contributing to LearnPilot.

LearnPilot is an open-source project, and contributions that improve the application, its code, or the overall learning experience are welcome.

## Before you start

Before working on a contribution, please contact the project maintainer with a short description of:

- What you want to change
- Why you think it would improve LearnPilot
- How you plan to implement it, if you already have an idea

This helps avoid duplicated work and makes sure larger changes fit the direction of the project.

## Getting started

Once your idea has been discussed, you can:

1. Fork or clone the repository.
2. Set up the development environment using the [Development Guide](./docs/development.md).
3. Create a branch for your work.
4. Make your changes.
5. Test the changes locally.
6. Commit your work with a clear commit message.
7. Open a pull request describing what you changed and why.

## What can you contribute?

Contributions can include anything that meaningfully improves LearnPilot, such as:

- New learning features
- Improvements to existing features
- Bug fixes
- Performance improvements
- Refactoring and cleaner code
- Better accessibility or usability
- Improved error handling
- Security improvements
- Documentation improvements
- Developer tooling and infrastructure

If you're unsure whether an idea is useful or appropriate, ask first. It is completely fine to reach out before writing any code.

## Questions and discussion

You can contact the project maintainer at any point during development.

Whether you're unsure about the architecture, stuck on an implementation detail, have found a bug, or simply want feedback on an idea, feel free to ask.

You don't need to wait until your contribution is finished.

## Pull requests

When opening a pull request:

- Clearly explain what you changed.
- Explain why the change is useful.
- Mention any important implementation details.
- Include relevant screenshots or examples for UI changes.
- Make sure the project builds and runs correctly.
- Make sure you haven't included secrets or private credentials.

Pull requests may be reviewed and discussed before being merged.

## Keep contributions focused

Try to keep each pull request focused on one feature, fix, or related group of changes.

Large changes are welcome, but breaking them into smaller, understandable contributions makes them easier to review and maintain.

## Code quality

Contributions should follow the existing structure and conventions of the project.

Before submitting a pull request, make sure:

- The code is readable and maintainable.
- Existing functionality still works.
- New functionality is tested where appropriate.
- No unnecessary dependencies are introduced.
- No secrets are committed.
- Documentation is updated when the change affects how LearnPilot is used or developed.

## A simple rule

If your contribution makes LearnPilot **more useful, more reliable, easier to maintain, or better to develop**, it is probably worth proposing.

When in doubt, reach out.
